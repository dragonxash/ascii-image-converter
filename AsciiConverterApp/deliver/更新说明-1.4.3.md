# 更新说明 — 1.4.3

**版本**：1.4.3（versionCode 11）
**上一版**：1.4.2（versionCode 10）
**改动主题**：预览区支持**双指缩放**（图片预览 + 样式设置里的「文本预览」都能放）

---

## 一、这一版在解决什么

龙哥的原话：

> 导入图片之后的那个预览和样式设置的文本预览能不能全都让双指放大？

先对齐一下这两个说法指的是什么——它们其实是**同一块预览区的两种模式**：

| 说法 | 实际是 | 什么时候显示 |
| --- | --- | --- |
| 「导入图片之后的那个预览」 | 主界面预览区，`ascii_art_iv` | 默认（图片模式） |
| 「样式设置的文本预览」 | 同一块区域的 `ascii_text_tv` | 样式设置里打开「**文本预览**」开关之后 |

（「文本预览」正是 `settings_text_mode` 这个字符串的值，所以这个对应关系不用猜。）

所以这一版就是把**主界面预览区**这块地方改成可缩放。

### 为什么值得做

固定宽度的预览里，字符画越小越看不清——字符宽度拉到几百列时，每个字符只有一两个像素，
那段字符到底画的是什么，根本无从判断。放大之后才能"贴脸看"细节，
也才能确认某些格子是不是映射错了字符。

---

## 二、为什么不能"加个 PhotoView 了事"

这个 App 的体积是个卖点（release 包 1.6 MB，从 45 MB 一路压下来的），
为一个预览区引一个第三方缩放库，等于为了几十行逻辑多背一个依赖。所以自己写。

但**自己写也不能只是"把 ScrollView 换成缩放的 ImageView"**，原因挺具体：

| 做法 | 为什么不行 |
| --- | --- |
| 保留 `ScrollView`，给内容加 `scaleX/scaleY` | `ScrollView` 的可滚动范围是**按子 View 的测量尺寸**算的。用 `scaleX` 放大之后测量尺寸没变，于是**滚不到被放大的部分**——放大后右下角一大片是死区，够不着 |
| 把内容的布局尺寸一起改大 | 会牵动文字重新排版。文本预览是**等宽字符**，一换行字符画就散架了 |
| 用 `HorizontalScrollView` 套 `ScrollView` | 解决了两轴，但还是**没有缩放**；而且两层的拦截逻辑叠在一起，手势会打架 |

结论：需要一个**自己管缩放和平移**的容器。于是新增 `ZoomPaneLayout.kt`。

---

## 三、`ZoomPaneLayout` 是怎么做的

一句话概括：**子 View 的布局尺寸一律不动，只在绘制时叠一层变换**。

- 缩放记在 `scale`；
- 平移记成「内容左上角离视口左上角多远」（`offsetX/offsetY`，永远 ≤ 0）；
- 支点固定在内容左上角，于是「内容上的点 x」画出来的位置就是 `offset + x * scale`——
  夹取范围、焦点换算都变成一行算术。

### 缩放：手指按住的那个点必须停在原地

支点在左上角时，令焦点 `f` 在缩放前后对得上，就能解出新的偏移：

```kotlin
val ratio = next / scale
offsetX = focusX - (focusX - offsetX) * ratio
offsetY = focusY - (focusY - offsetY) * ratio
```

不做这一步的话，捏合时内容会一边放大一边"跑"，想放大的那个字符会溜走。

倍数夹在 **1× ~ 8×**：最小 1× 是因为缩到比铺满还小没有意义（顺便让"往里捏到底 = 复位"
成为一条自然发现的路）；上限 8× 是因为再大只能看到一堆色块。

### 测量：宽度分两种情况（**这是最容易踩的一步**）

| 内容写的是 | 怎么量 | 为什么 |
| --- | --- | --- |
| `match_parent`（图片模式的图） | 按视口宽度 **EXACTLY** | 图本来就该铺满宽度 |
| `wrap_content`（文本模式的字） | **UNSPECIFIED**（不设上限） | 如果卡住宽度，文字会被挤着**换行**，等宽字符一换行，字符画就散了 |

高度一律不设上限——内容比视口高是常态（本来就靠滚动看下半截），
露到外面的部分交给 `FrameLayout` 自带的 `clipChildren` 裁掉。

这条判断写在 `measureChildWithMargins()` 里（`FrameLayout` 量孩子走的就是这个钩子），
判断方式和 `HorizontalScrollView` 一致。

### 触摸：什么时候归我们，什么时候归子 View

文本预览是 `textIsSelectable` 的——**长按要能选字、单击要能定位光标**。
手势一抢狠了，这个功能就废了。所以规则定得比较保守：

| 手势 | 归谁 | 理由 |
| --- | --- | --- |
| 双指（≥2 个指针） | **我们** | 一定是缩放，优先 |
| 第二根手指落下 | **我们**（从子 View 手里收回来） | 不收的话第一根手指的事件在子 View 那里，缩放起不来 |
| 单指 + 内容比视口大 | **我们** | 这就是原来的"滚动"，必须保留 |
| 单指 + 内容放得下 | **子 View** | 让选字、定位光标正常工作 |
| 单指但没过触摸阈值 | **子 View** | 点一下、长按都不能被抢 |

另外 `ScaleGestureDetector` 的 **quick scale（双击后按住拖动）关掉了**——
双击在文本预览里是选词，留着它就会和选字打架。

### 平移：夹取 + 惯性滑动

- 内容不比视口大 → 偏移归 0（也就是不能拖），夹取范围就是 `[视口-内容*scale, 0]`。
- 内容尺寸变了（换图、换字号、转屏、切模式）会在 `onLayout` 里**重新夹一次**，
  否则换张小图之后会停在屏幕外面。
- 松手带惯性滑动。**不依赖 `computeScroll()`**——那个要父容器主动来调，
  自己 `postOnAnimation` 一帧一帧推更可控。
- 两个坑顺手堵了：
  - **捏过就不甩**。捏合时两根手指是往两边张的，算出来的"速度"大得离谱，
    松手会把画面直接甩飞。
  - **速度追踪放在 `dispatchTouchEvent` 里**。`onTouchEvent` 只在我们抢到手势之后才收得到事件，
    被抢之前那一段（在子 View 手里）的速度数据不能丢，否则算不出甩动速度。

### RTL：内容必须钉在左上角

`AndroidManifest` 里 `android:supportsRtl="true"`。缩放平移这套算法的前提是
「内容左上角就在视口左上角」，而 `FrameLayout` 默认给的是 `Gravity.START`——
阿拉伯语这类 RTL 语言下 START 会解析成**右对齐**，内容直接被推到屏幕外，缩放拖动全乱。

处理方式：布局里写死 `android:layout_gravity="top|left"`（不是 `start`），
并在 `onFinishInflate()` 里再用代码钉一次，免得以后有人在 XML 里漏掉。

## 四、怎么退出放大

放大之后右下角出现一个半透明小角标：**`1.8× 复位`**，点一下回 1×。

为什么不做"双击复位"：双击在文本预览里是选词，抢过来会把「可长按复制」这个功能弄坏。

所以给了两条路：

1. 点右下角那个角标；
2. **往里捏到底**——最小倍数就是 1×，捏到尽头自然就复位了。

另外，**换图 / 换导入的文字会自动回到 1×**；但**调样式不会**——
用户往往是先放大看清细节、再拖滑杆微调，每调一次就被弹回原始大小会很难受。

## 六、怎么验证

```bash
python verify_preview_zoom.py    # ← 本轮新增，50 项
# 另外 9 个回归脚本
```

`verify_preview_zoom.py` 盯的是这一版**新引入的那类风险**——
「改错了也不会崩、只是没法用」：

| 检查的东西 | 防的是什么 |
| --- | --- |
| 预览区容器是 `ZoomPaneLayout` 且**布局里不再有 ScrollView** | 有人把它换回去 → 放大后再也滚不动 |
| 只有一个直接子 View / 内容是 FrameLayout | 摆放契约被破坏 |
| `layout_gravity` 是 `top\|left` 且代码里也钉了 | RTL 下内容跑到屏幕外 |
| `match_parent` 走 EXACTLY、`wrap_content` 走 UNSPECIFIED | 文字被卡宽度 → 换行 → 字符画散架 |
| 关掉 quick scale | 双击选词被抢 |
| 单指拖动要过触摸阈值、且 `!canPan()` 时一律不接管 | 文本预览**选不了字** |
| 缩放时焦点固定、倍数被夹住、MIN_SCALE = 1 | 捏合时内容乱跑 / 无限放大 |
| 捏过不甩、`postOnAnimation` 自己推、`VelocityTracker` 及时回收 | 松手画面飞走 / 内存泄漏 |
| 复位角标存在、点得动、≤1× 时隐藏 | 用户被**困在放大状态** |
| 换图/换文字复位、调样式不复位 | 上一张的倍数跟到下一张 / 调参数被弹回 |
| 中英 `preview_zoom_reset` 都在且占位符一致 | 切语言崩 |

另外把用到的平台 API 逐个查了一遍**有没有被标记废弃**
（`VelocityTracker` / `ScaleGestureDetector` / `OverScroller` / `ViewConfiguration`），
确认全部干净——这个工程要求代码级编译警告为 0，用到一个废弃 API 就会破功。

## 七、这一版**没做**的两件事（写清楚，不含糊）

1. **「文字结果」面板没有加缩放。**
   就是你从菜单点开、显示完整文本那个面板（里面有复制 / 分享 / 存文本三个按钮）。
   它现在是 `ScrollView` + `HorizontalScrollView` 两层套着，**能上下左右滚，但不能缩放**。
   没顺手改的原因：它是弹窗里一个固定 240dp 高的小框，换成缩放容器之后
   「文字不换行」这条得靠另一套测量规则来保，和主预览区不完全一样，
   属于要单独验证的一块。**要的话说一声，下一版加。**

2. **没做"缩放倍数记忆"。** 换图之后固定回到 1×，不会记住上次放到多少。
   如果你更希望"下一张也保持同样的倍数"，也说一声。

## 九、还是**没有真机测试**

老规矩，写清楚：**开发机上没有设备、也没有可用的模拟器**。
所有验证都是「编译 + 包内反解核对 + 静态结构校验 + 算法级离线验证」。

而这一版的性质决定了我更不放心：**手势是一类必须上手才知道对不对的东西**。
捏合的手感、阈值合不合适、选字有没有被影响、惯性滑动快不快——
这些静态校验一条都测不出来。

请龙哥重点试这几条：

1. **图片模式**：双指放大到 4~5× → 单指拖动看四周 → 点右下角「复位」回 1×
2. **往里捏**，看是不是能一路捏回 1×（这是"退出放大"的第二条路）
3. **文本模式**（样式设置里开「文本预览」）：放大后**长按选字**、复制一段 ——
   确认选字还能用（这是我做手势分配时最小心的地方）
4. **长图**：选一张很长的图，在 1× 状态单指上下拖 —— 确认原来的"滚动看下半截"没丢
5. **换图**：放大之后换一张图，确认倍数自动回到 1×
6. **调样式**：放大之后拖「字符宽度」滑杆，确认倍数**没被重置**（这是有意保留的）
7. **甩动**：快速拖动一下松手，看惯性滑动跟不跟手、会不会飞过头

任何一条不对，把现象说出来我改。要是能顺手抓一份 logcat 就更好了
（`排错说明-如何取错误详情.md` 里有步骤）。
