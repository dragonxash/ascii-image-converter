## 一、根因：`OverScroller.fling()` 的起始位置被我写成了 `0, 0`

1.4.3 里那段甩动的代码是这样写的：

```kotlin
// 1.4.3（错的）
scroller.fling(
    0, 0,                    // ← 起始滚动位置
    vx.toInt(), vy.toInt(),  // 速度
    minOffsetX().toInt(), 0, // 横向范围
    minOffsetY().toInt(), 0  // 纵向范围
)
```

`OverScroller.fling()` 的前两个参数是 **起始滚动位置**——它内部的 `currX` / `currY`
就是从这个值开始算的，**不是"用不到的占位"**。

而负责推进惯性的那个 `flingStep` 里是这么取的：

```kotlin
offsetX = scroller.currX.toFloat()
offsetY = scroller.currY.toFloat()
```

两处一接上，后果就出来了：

| 时刻 | `scroller.currX` | `offsetX` | 画面 |
| --- | --- | --- | --- |
| 放大到 2×、拖到左下角 | — | 比如 `-500` | 正常 |
| **松手的瞬间** | 从 **0** 开始 | **被按回 0** | **跳回左上角** |
| 甩动第一帧 | ≈ 0 + 一点点 | ≈ 0 | 从左上角开始滑 |

所以你看到的是「一挪动就自动跑到左上角」——**先跳回左上角，再从那里带着速度甩出去**。
手一快，这个跳变就特别明显；慢慢拖到没速度才松手（没触发甩动）反而看不出来。

**为什么会写错**：`fling` 有 8 个参数，中间还夹着 4 个范围值，很容易把前两个
"起始位置"当成可以随便填的默认值。我上一版就是这么想岔的。

---

## 二、改法

```kotlin
// 1.4.4（对的）
removeCallbacks(flingStep)          // 起新惯性前先撤掉上一轮的，免得两个 runnable 叠加
scroller.fling(
    offsetX.toInt(), offsetY.toInt(),   // ← 从**当前**位置起步
    vx.toInt(), vy.toInt(),
    minOffsetX().toInt(), 0,
    minOffsetY().toInt(), 0
)
```

顺带补的一句 `removeCallbacks(flingStep)` 是个隐患保险：
`flingStep` 是 `postOnAnimation` 自驱的，如果上一轮的回调还没跑到"自己停"就被新的一轮接上，
两个 runnable 会同时推进，速度直接翻倍。原来靠"必须先 ACTION_DOWN 才能再 UP"侥幸躲过去，
但它不该靠侥幸。

## 三、怎么保证不再犯

`verify_preview_zoom.py` 加了 **3 条**（50 → 53 项）：

| 新增检查 | 防的是什么 |
| --- | --- |
| 惯性滑动从**当前**平移量起步，不是写死的 0 | 就是这一版的 bug。断言 `fling()` 头两个实参是 `offsetX…` / `offsetY…` |
| 惯性滑动的滚动范围 = 当前可平移范围 | 范围写错 → 能滑出夹取区间，露出空白 |
| 起新惯性前先撤掉上一轮回调 | 两个 runnable 叠加 → 速度翻倍 |

另外把原来一条**形同虚设**的检查补严了：

> 「onDetachedFromWindow 里停掉惯性并回收」——原来是在**整个文件**里找
> `removeCallbacks(flingStep)`。可 `startFling` 里现在也有这一句，
> 就算有人把 `onDetachedFromWindow` 里那句删了，这条检查照样通过。
> 改成只在该**函数体**里找。

**并且做了反向验证**：把起始参数改回 `0, 0` 喂给检查逻辑，确认它会报 FAIL
（而不是"看着有检查、实际永远为真"）。检查本身测不出问题，就等于没有检查。

## 八、还是**没有真机测试**

写清楚：开发机上没有设备、也没有可用的模拟器。
这次的情况和以往不太一样——**症状是你在真机上给的，根因是代码走查定下来的，
两者严丝合缝**（`fling` 起点为 0 → 第一帧 `currX≈0` → `offsetX` 被按回 0 → 跳左上角），
所以我对这个修法比对以往任何一次都更有把握。

但"更有把握"不等于"验过了"。请再装一次，重点试：

1. 放大到 2~3×，**往左边快拖一下松手** → 应该是接着当前的位置继续滑，不再跳回左上角
2. 放大后拖到右下角，再快拖一下 → 同样不该跳
3. 放大后**慢慢拖、松手**（速度不够不触发甩动）→ 位置应原地停住
4. 拖到边缘继续拖 → 应该顶住不动，不出现空白
5. 顺带把 1.4.3 那几条没验的再走一遍：**文本模式放大后能不能长按选字**、
   长图 1× 下单指上下滚、放大后换图是否回 1×、放大后拖样式滑杆倍数**不该**被重置
