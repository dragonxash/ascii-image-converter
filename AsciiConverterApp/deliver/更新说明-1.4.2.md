# 更新说明 — 1.4.2

**版本**：1.4.2（versionCode 10）
**上一版**：1.4.1（versionCode 9）
**改动主题**：给**批量转换**补上「文件浏览器」这条选图通道

> 1.4.1 修的是「系统相册选的图读不出来」。修完之后发现还有个更大的漏洞：
> 单图页有两条路可选，**批量页只有相册一条**——相册那条路一挂，批量功能就是死路一条。
> 这一版把第二条路补上。

---

## 一、缺口是怎么被发现的

龙哥的原话：

> 就是那个多选里面没有文件浏览器，只能相册选，但是却全部提示失败，读不到数据

拆开看是两件事叠在一起：

| # | 现象 | 性质 |
| --- | --- | --- |
| 1 | 批量页选图**只能走相册**（照片选择器） | **设计缺口**——主界面早就给了「系统相册 / 文件选择器」二选一，批量页没跟上 |
| 2 | 相册选的图**全部读不出来** | 1.4.1 修的那个病（相册临时授权经不起反复开），批量页尤其严重——`RecyclerView` 滚动会反复重新绑定，每绑一次就去开一次 Uri |

单看第 2 条，1.4.1 已经把"只读一次"那层改完了，理论上批量页也该跟着好。
但第 1 条让风险从"可能出错"升级成"**出错就没救**"：

> 单图页相册挂了，用户点「换文件浏览器重选」还能干活。
> 批量页相册挂了 —— **它没有别的按钮可点**。

这不是"少个便利功能"，是**唯一的门被堵死**。

---

## 二、改了什么

### 1. 批量页选图改成"二选一"，不再替用户拍板

点右上角「选图」现在弹一个小对话框：

| 选项 | 走哪条路 | 授权 |
| --- | --- | --- |
| 系统相册（可多选） | 照片选择器 `PickMultipleVisualMedia` | 临时 |
| **文件浏览器（可多选）** | SAF `OpenMultipleDocuments` | **可持久化** |

和主界面 `showSourceChooser()` 是同一个思路：**这台机器上哪条通道好使，只有用户知道**，
所以两条都摆在明面上，一条不通还有另一条。

### 2. 新增 SAF 多选入口

`PersistableOpenMultipleDocuments`：继承 `OpenMultipleDocuments`，额外加
`FLAG_GRANT_PERSISTABLE_URI_PERMISSION`，选完对每个 Uri 调 `takePersistableUriPermission`。

- **为什么值得多要一个持久化权限**：批量页退出时会把中转文件清掉，万一之后还想拿同一个
  Uri 补捞一次，权限还在才捞得动。
- **只选一张也不会出问题**：`OpenMultipleDocuments` 内部的 `getClipDataUris` 已经处理了
  "只选一张时 `intent.data` 里直接有 uri"这个分支（反汇编 activity 1.11.0 确认过），
  不用自己写单选兜底。
- 反过来的情况也成立：SAF 多选签名的返回类型就是 `List<Uri>`，直接喂给现有的
  `addItems(List<Uri>)`，**转换链路一行都不用改**。

### 3. 张数封顶（这条是 SAF 带进来的新风险）

相册那条路有 `PickMultipleVisualMedia(50)` 兜着，**SAF 没有张数上限**——
用户一次勾 300 张，中转文件和位图能把内存和 cache 目录一起顶满。

现在两条路统一按 50 张封顶，超出的丢掉并提示
「一次最多 50 张，多出来的已忽略」。

### 4. 整批都读不出来时，主动给一条换道的路

转换跑完如果**一张都没成**，弹窗：

> **这批图都读不出来**
> 多半是「系统相册」这条通道在这台机器上不好使，跟图片本身没关系。
> 点下面的按钮，换成「文件浏览器」重选一遍通常就好了。
>
> `[换文件浏览器重选]`　`[知道了]`

点「换文件浏览器重选」会：

1. **先把那些注定读不出来的项清掉**——它们全是同一个 Uri，重试多少次结果都一样，
   留着只会让用户以为"这软件读不了我的图"；
2. 直接跳进 SAF 多选。

**为什么值得单做这一步**：用户在这个页面上看到一屏「失败」，最容易得出的结论是
"图片有问题"或"App 有问题"，而不是"这条通道有问题"。把换道按钮直接摆在失败现场，
比自己回去想办法换入口短得多。

### 5. 空列表提示写清有两条通道

原来：`还没选图片，点右上角「选图」`
现在：`还没选图片。点右上角「选图」，相册和文件浏览器两条路都能进，哪条通用哪条。`

功能藏起来等于没有。这一句是这次改动里最便宜、也最有用的一处。

## 四、怎么验证

```bash
# 全套校验脚本（9 个，全过）
python verify_ansi_roundtrip.py
python verify_consts.py
python verify_pc98_dither.py
python verify_pc98_palette.py
python verify_quantize_before_after.py
python verify_release_chartable.py
python verify_source_pipeline.py     # ← 本轮扩容到 51 项
python verify_spectrum_color.py
python verify_string_formats.py
```

`verify_source_pipeline.py` 本轮新增的 10 项，是把这次的教训钉成结构特征：

| 检查项 | 防的是什么 |
| --- | --- |
| 批量页有 SAF 多选入口 | 通道本身在不在 |
| SAF 入口真被挂到选图流程上 | 有没有"定义了 launcher 但从没人调" |
| 两条通道由用户二选一，不替用户拍板 | 别又退化成"只有一条路" |
| 菜单点「选图」走的是二选一 | 菜单有没有被改回直接调起相册 |
| 菜单里不再直接调起相册 | 同上（反向断言） |
| SAF 拿到的也是可持久化读权限 | 权限标志别漏 |
| 整批失败时会给出换道的出口 | 死路还有没有 |
| 换道前把注定读不出来的项清掉 | 清空 → 跳 SAF 的顺序有没有被拆散 |
| 文件浏览器多选也有张数封顶 | SAF 无上限这个新风险 |
| 两条通道都兜住了调起失败 | 两个入口都得有兜底 |

另外顺手修了三处工具自己身上的问题：

- **`verify_consts.py` 一直是 FAIL 的**：它按"数组收尾括号前必然换行"写正则
  （`(.*?)\n\s*\)`），而 `lib-ref/AsciiArtImageFilter.kt` 里那张表是一整行写完的，
  排版一变整个匹配不上。改成找最近的收尾括号。
  **顺带发现它第二层逻辑也有毛病**：它拿**字面量**比 `0.0` 和 `0.00`，
  这两个是同一个数，却会被判成"不一致"——差点去"修"一张本来没错的表。改成按数值比。
- **`verify_string_formats.py` 在 `deliver/` 里跑不起来**：它写死了
  `脚本所在目录 / "AsciiConverterApp" / ...`，而 `deliver/` 底下没有这个子目录，
  一跑就崩在"读不到 strings.xml"。**也就是说交付目录里那份一直是个摆设**。
  改成从脚本所在目录逐级往上找 `AsciiConverterApp/app/src/main`，找不到才退回本机绝对路径——
  两份现在都能跑。
- **根目录少了 `verify_quantize_before_after.py`**（只在 `deliver/` 里有），已补齐。

> 改完两处共 17 份脚本（根目录 9 + `deliver/` 8）**全部 PASS**。

## 六、这次仍然**没有做真机测试**

写清楚，不含糊：

- **开发机上没有设备、也没有可用的模拟器**，所有验证都是
  「编译 + 包内反解核对 + 静态结构校验 + 算法级离线验证」。
- 能复现相册 ENOENT 的只有龙哥那台**一加 13（ColorOS / Android 15）**。
- **批量页 SAF 多选这条路我一次都没在真机上点过**——它的正确性依据是：
  `OpenMultipleDocuments` 是 androidx 官方契约、`getClipDataUris` 的单选分支已反汇编确认、
  返回类型 `List<Uri>` 与现有 `addItems` 签名一致。

请龙哥重点试这几条：

1. 批量页 → 选图 → 弹窗里选「**文件浏览器（可多选）**」→ 一次勾 5~10 张 → 全部转换 → 全部保存。
2. 同一批图，用「系统相册」选，看是否还是全部失败（**这是预期内的**，通道问题没变）。
3. 上一条失败后，弹窗点「换文件浏览器重选」，确认列表被清空、并直接跳进文件浏览器。
4. 随便多选个十几张，然后**上下滚动列表**，看缩略图会不会消失。
5. 一次勾 60 张以上，确认提示「一次最多 50 张」并且只进 50 张。

任何一步报错，用菜单里的「上次错误」把完整堆栈取出来发我。
