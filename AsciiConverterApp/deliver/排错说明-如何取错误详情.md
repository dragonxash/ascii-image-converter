# 排错说明 — 怎么把错误详情取出来

这个包（**1.0.1**）加了一套错误取证机制。之前的版本出错只弹半句话（`e.message`），
很多异常这个字段是空的或者没意义，定位不了。现在改成完整堆栈。

---

## 出错时会怎样

| 场景 | 表现 |
| --- | --- |
| 转换/保存/选图出错 | 弹一个标题为「**XX 出错**」的对话框，里面有**完整堆栈** |
| 对话框底部「**复制详情**」 | 一键复制全文，直接发出来就行 |
| 应用直接崩掉（界面消失） | 崩溃堆栈会自己写进文件，重开 App 后从右上角菜单「**查看上次错误**」取 |

复制出来的内容长这样：

```
时间: 2026-09-17 12:45:03
场景: 转换图片
机型: Xiaomi 23049RAD8C
系统: Android 14 (API 34)
异常: java.lang.OutOfMemoryError
信息: Failed to allocate a 419430412 byte allocation...
--- 堆栈 ---
java.lang.OutOfMemoryError: ...
	at android.graphics.Bitmap.createBitmap(Bitmap.java:...)
	...
```

有这几行基本就能定位到具体是哪一步炸的。

---

## 想看日志的话

用数据线连电脑，装好 adb 后：

```bash
adb logcat -s AsciiConverter:E
```

只看这个 App 的错误日志（tag 是 `AsciiConverter`）。

崩溃堆栈同时也落在手机里：`/data/data/com.dragonxash.asciiconverter/cache/last-error.txt`
（需要 root 或 `adb shell run-as com.dragonxash.asciiconverter cat cache/last-error.txt` 才能直接看，
一般用上面那个菜单入口就够了）。

## 这一版顺手修的东西

| 问题 | 说明 |
| --- | --- |
| 大图降采样不生效 | `sampleSizeFor` 的判断条件写错了一轮，4000px 的照片经过它还是 4000px，等于没降采样。已改成「缩放后仍超过上限就再翻一倍」，现在最长边真的会被压到 2400px 以内 |
| 极端长宽比可能爆内存 | 超长截图 / 细长条会算出上亿像素的画布。加了 800 万像素的输出预算，超了就等比缩回来，而不是直接 OOM |
| 选图、拍照、保存没兜异常 | 以前任何一个环节抛异常都是直接闪退，现在统一兜住并弹出详情 |
| 外部「分享到」可能 NPE | `ClipData` 的 item 允许没有 uri，以前直接取会空指针，已判空 |
| 批量按钮的异常处理不一致 | 改成和别处统一，都走完整堆栈对话框 |

## 还是不行的话

把对话框里复制出来的内容发我，我按堆栈改。
如果连对话框都没弹（比如打开就闪退），就用「查看上次错误」把内容取出来发我。
