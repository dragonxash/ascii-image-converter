## 一、先回答你的问题：PC-98 到底有没有固定颜色？

**你说对了一半，另一半是术语问题。**

### 对的那半：没有固定色表

PC-98 的 16 个颜色**不是硬件写死的**，是一张**可编程调色板**——每个程序（每张图）自己往里填。
你说的「按构图选 16 个颜色加进去」，思路完全正确，我实现的就是这个。

只补一点：**不是"随机"选**，是算出来的。随机挑 16 个颜色会很难看，
实际做法是从画面里挑**最有代表性的** 16 个（我用的是中位切分）。
准确说是"自动跟着构图走"，而不是"随机"。

### 术语要纠正的那半：不是 16 bit，是 16 色

| 说法 | 对不对 | 实际 |
| --- | --- | --- |
| 同屏不超过 **16 色** | ✅ 对 | 经典 PC-98（PC-9801）就是 640×400 **16 色同屏** |
| 不超过 **16 bit** | ❌ 不对 | 16 bit 色 = **65536** 色，差得远 |

把这两个数拆开看：

| 概念 | PC-98 的实际值 |
| --- | --- |
| 同屏能显示几种色 | **16 色** |
| 调色板一共多少色 | **4096 色** |
| 调色板精度 | **12 位** = 每通道 4 bit = 每通道 16 级 |
| 每像素占多少位 | 4 bit（所以叫"16 色模式"） |

所以 4096 色的来源是 **4 bit × 3 通道 = 12 bit**，不是 16 bit。
至于 16 bit 色（65536 色）——那是 PC-9821 之后某些模式、以及同期 SXGA 一类显卡的事，
跟经典 PC-98 的游戏画面不是一回事。

（顺带一提：更早的 PC-9801VM/UV 那一代其实只有 **8 色同屏**，
要插 PC-9801-24 扩展板才加到 16 色。我在验证脚本里把 8 色也一起测了。）

### 这些数字在 App 里是怎么落地的

「16 色（PC-98 风）」格式**唯一照搬的就是这两条硬约束**：

| PC-98 的约束 | App 里的实现 | 怎么验证 |
| --- | --- | --- |
| 同屏 16 色 | 中位切分从画面挑 16 个代表色 | 调色板恰好 16 色、无重复 |
| 每通道 4 bit | `snapToPc98()` 把每个通道吸到 16 级（×17） | 通道值**全是 17 的倍数** |

第二条是关键——普通量化出来的通道值是乱七八糟的 0~255，
吸附之后**一定是 17 的倍数**（0, 17, 34, … 255），这才是那套调色板的真实精度。
导出的 16 色 txt 里，颜色码全是 17 的倍数，那个味道就对了。

**没有固定色表**这件事，我用脚本实测了：五组不同色系的画面（黄昏、深海、灰阶、赛博霓虹、森林），
各自挑出的调色板**两两之间的重叠是 0/16**（只有"深海"和"赛博霓虹"共享 1 色，都偏暗蓝）。
灰阶画面的调色板则全是 R=G=B 的灰——完全跟着内容走。

## 二、新增：只保留色块（去掉字符）

**样式面板里多了一个开关：`只保留色块`。**

打开后**整格填满该格的原图颜色，不画任何字符**——等于把画面降采样成一张马赛克。
块的大小由「字符宽度」控制（列数越少块越大，越有像素画的颗粒感）。

### 几个实现上的细节

| 细节 | 说明 |
| --- | --- |
| **空格也一起填** | 字符模式下空格等于"留白"，色块模式必须一起填，否则画面会漏出一堆背景色的洞 |
| **跨格补 1 像素** | 格子宽高常常除不尽，相邻块之间会露出发丝般的缝，往外多画 1 像素盖掉 |
| **批量页也吃到了** | 样式参数会带到批量页，那里也能出色块 |
| **旋转屏幕 / 切语言不丢** | 状态保存里加了这一项 |

### 和「PC-98 16 色」叠起来 = 复古像素画

这才是这套组合的正经用法：

```
原图 ──► 色块降采样（16×8 块）──► 挑 16 色 + 吸到 12 位 ──► 复古像素画
```

验证脚本实测：16×8 共 128 个色块，量化后**恰好 16 色，且 16 个色位全部用上**，
所有颜色都在 12 位精度上。128 块用 16 色画出来——这正是当年 PC-98 画师的处境。

### 色块模式下自动置灰的选项

这几项在色块模式下不参与运算（没有字符可画，配色也不该被"单色"掐掉），
所以**自动变灰**，免得你点了没反应：

- 字符反转（亮暗对调）—— 只影响"选哪个字符"，没字符就没意义
- 颜色反转 —— 是把字符形状从色块里抠出来，没字符可抠
- 保留原图颜色 —— 色块模式一律用原图颜色，不然就是一整块纯色
- 等宽字体 —— 没有字
- 原图彩色填充 —— 同理

「字符宽度」和「文本预览」保持可用。

> 提示：色块模式下切到「16 色（PC-98 风）」文本格式，
> 导出的 txt 就是那份像素画调色板的颜色码。想发给谁都能看，导「纯字符」格式。

## 三、顺手修掉一个浪费色位的 bug

写这版的验证脚本时**挖出来的**，跟 1.2.0 的算法有关，一并修了。

### 症状

16 个槽位里出现**重复颜色**，最多的场景（森林，平涂为主）只剩 **6 种**不同颜色：

```
森林    #112211 #337733 #558833 #224422 #558833 #77AA55 #112211 #224422 ...
                 ↑重复2次        ↑重复3次  ↑重复4次          ↑重复2次    ↑重复5次
赛博霓虹 #331144 #441166 #FF3399 #222255 #11EEEE ... #FF3399 #FF3399 #EE2299 #FF3399 #FF3399
                          ↑重复5次                      ↑重复5次
```

**16 个槽位，6 种颜色**——白扔了 10 个色位。

### 根因（两个，叠在一起）

1. **判停条件用错了维度**。中位切分是按"桶的个数"停下（够 16 个桶就停），
   但每个桶的代表色是**平均值**，而平均值会被 `snapToPc98()` 吸到 12 位网格上——
   两个不同的桶很容易撞到**同一个格点**，于是 16 个桶给出一堆重复色。
2. **选桶的标准也用错了**。原来挑"原始通道跨度最大"的桶来劈。
   但跨度大 ≠ 劈开能多分出一个色位：一个跨度很大、量化后却只落在一个格点上的桶，
   劈了也白劈。

再叠上一条隐患：**大块平涂的画面最容易踩坑**——而这恰好就是 PC-98 CG 的典型特征
（赛璐璐上色，大面积纯色块）。实测数据把这个规律坐实了：

| 画面类型 | 修复前 16 个槽位里的实际色数 |
| --- | --- |
| 森林（**平涂为主**） | **6 种** |
| 赛博霓虹（**平涂为主**） | **11 种** |
| 黄昏草原（渐变） | 13 种 |
| 深海（渐变） | 15 种 |

**越是平涂的画面，浪费越狠。** 所以这个 bug 对目标场景伤害最大。
（反过来说：拿颜色分布很散的"照片"当测试样本，根本发现不了这个 bug。）

### 修法

```kotlin
// 判停：看"不同颜色的个数"，不看"桶的个数"
while (palette.toSet().size < maxColors) {

    // 选桶：按"桶内还有几种量化色"挑，并列时再看原始跨度
    val distinct = snappedColorCount(bucket)      // ← 关键
    if (distinct > bestDistinct || (distinct == bestDistinct && span > bestSpan)) ...

    // 劈完取平均值后，最后再 distinct() 兜一次底
}
```

`snappedColorCount()` 数到 8 种就提前返回——只是用来给桶排序，
早期每个桶都含成百上千种色，全量去重纯属浪费。
另加 `guard = maxColors * 4` 防止劈分一直不增加色数时循环跑飞。

### 效果

| 场景 | 修复前 | 修复后 | 理论可达上限 |
| --- | --- | --- | --- |
| 森林 | **6 种** | **16 色** | 16 |
| 赛博霓虹 | 11 种 | 16 色 | 16 |
| 黄昏草原 | 13 种 | 16 色 | 16 |
| 深海 | 15 种 | 16 色 | 16 |
| 灰阶老照片 | 12 种 | 12 色 | **12** |

最后一行要解释一下：**12 是理论上限，不是没挑满**。
纯灰阶画面的所有颜色都落在灰轴（R=G=B）上，可用的格点只有 16 个灰阶；
而这组画面的灰度范围没铺满 0~255，能用的格点只有 12 个——
所以 12 色就是极限（修复前后都是 12，本来就到了天花板）。
脚本里是按「理论可达上限」判的，不是硬要求 16。
（源画面本身颜色不足 16 种时，返回更少也是对的，硬凑只会凑出重复色。）

## 六、怎么玩出 PC-98 味

1. 选一张图（galgame 的 CG 最合适——本来就是 16 色画的）
2. 打开「样式」→ 开 **`只保留色块`**
3. 「字符宽度」拉到 **80~160** 之间（列数越少块越大，越有颗粒感）
4. 需要导出去看的话，工具栏 `A` → 选 **「16 色（PC-98 风）」**，颜色码全是 17 的倍数

想要更接近原作的观感，第 3 步可以试 **320 列**（PC-98 是 640×400，横向对折一下差不多）。
