# ASCII 图片转换器

一个把照片变成字符画（ASCII Art）的安卓 App，**双向可用**：图片能转成字符画，字符画也能转回图片。从 [tAsciiArtPlayer](https://github.com/Tans5/tAsciiArtPlayer) 的图片转换模块抽出来独立成型，去掉了视频播放和文件传输那一整套依赖，安装包从 45MB 压到 1.6MB 左右。

- **包名**：`com.dragonxash.asciiconverter`
- **版本**：1.5.0（versionCode 14）
- **系统要求**：Android 8.0（API 26）及以上
- **联网**：不联网。整个转换流程纯本地跑，不上传任何图片。
- **界面语言**：默认简体中文，可在右上角菜单里切换（简体中文 / English / **日本語** / 跟随系统）

> **版本沿革**
> - **1.5.0** — **新增日文界面**（第 3 门语言）。加一门语言要同时动四处（枚举 + 资源目录 + `locales_config` + `localeFilters`），**任何一处漏掉都是静默失效**：漏资源会静默回退成中文、漏 `localeFilters` 会被 aapt 直接裁掉资源（装机后"选日语没反应"）。为此补了 `verify_locales.py` 把四处钉住（含反向验证），校验脚本变成**根目录 11 个 / `deliver/` 10 个**。见 `更新说明-1.5.0.md`

> - **1.4.4** — 修掉 1.4.3 的**「一挪动就跳回左上角」**：根因是 `OverScroller.fling()` 的起始滚动位置被写成了 `0, 0`，而推进惯性的回调里是 `offsetX = scroller.currX`，于是松手第一帧就把平移量按回 0。改成从**当前**平移量起步，并补上「起新惯性前先撤掉上一轮回调」。`verify_preview_zoom.py` 相应加了 3 条检查（50 → 53 项），其中起始位置那条做了反向验证。见 `更新说明-1.4.4.md`

> - **1.4.1** — 修掉**「系统相册选的图读不出来（ENOENT）」**：根因是每次转换都拿原始 Uri 重新解码，相册的临时授权经不起反复开（文件选择器给的是可持久化授权，所以它一直没事）。改成**选图时读一次、落到本地，之后只读本地文件**，并把 `PictureDecoder` 的 Uri 参数从类型上删掉。顺带加上**带退避重试**（云端图首开只是触发下载）、**照片选择器按 `_id` 走 MediaStore 兜底**、**失败时探测 provider 元信息**。见 `更新说明-1.4.1.md`

### 外部图片是怎么读进来的（1.4.1 重写）

这块是 1.4.1 修 ENOENT 的核心，单独说清楚。

两个选图入口给的授权**根本不是一回事**：

| 入口 | 授权性质 | 反复开同一个 Uri |
| --- | --- | --- |
| **系统相册**（照片选择器） | **临时**，绑在这次选图结果上 | ❌ 开几次就开始 `ENOENT` |
| **文件选择器**（SAF） | **可持久化**（App 主动申请的） | ✅ 爱开几次开几次 |

所以听到「文件浏览器选的图能读、系统相册选的不行」，基本可以断定代码在**反复开同一个 Uri**。
1.4.0 及以前确实是这样：**每次转换都用原始 Uri 重新解码一遍**，
而"每次参数变化都会重转"——拖一下滑杆可能就转了十几次，相册当然扛不住。

现在的规矩：**选图时读一次，落到本地，之后只读本地文件**。

| 环节 | 做法 |
| --- | --- |
| 落盘时机 | 选图回调里立刻做，**一次**（`SourceCache.materialize`） |
| 落盘位置 | `cacheDir/source/`，只留最近两张（留一张做缓冲，避免正在解码的那份被下一次选图删掉） |
| 转换时读什么 | 本地文件。`PictureDecoder` 的签名里**已经没有 Uri 参数**，想传都传不进来 |
| 界面重建后 | 存/读的是**本地文件路径**，不是会过期的 Uri；文件被系统清掉就当没选过图，不报错 |
| 关不掉的那次读取 | 7 种打开方式轮着试（含照片选择器按 `_id` 走 MediaStore 兜底），失败会**带退避重试 4 轮**（累计约 4 秒）——云端图的第一次打开往往只是"触发下载" |
| 真读不到时 | 弹窗上给一个 **「换文件浏览器重选」** 按钮，并把 provider 的元信息（`_data` / `is_pending` / 可见列）一起打出来，能直接看出是"图还在云端"还是"权限被拒" |

> **1.4.2 补的一刀**：上面这张表一直成立，但**批量页当时没有「文件选择器」这个入口**——
> 相册那条路一挂，批量功能就没有第二条路可走。现在批量页的「选图」也会问你要走哪条，
> 并且整批失败时直接给换道按钮。**入口少一个，兜底就等于没有。**

### 双向流程（1.1.0 新增）

以前只有「图片 → 字符画」单向，现在两头都通：

```
图片 / 拍照 ──► 字符画 ──► PNG（存相册 / 分享）
                  │
                  ├──► 文字结果面板 ──► 复制到剪贴板
                  │                 └─► 存为 .txt（下载目录）
                  │                 └─► 分享 .txt
                  │
        剪贴板 ◄──┘
          .txt ◄──┘
                  │
                  └──► 导入面板 ──► 图片（可继续调样式、存 PNG）
```

**文字结果面板**（工具栏 `A` 图标）

| 部件 | 说明 |
| --- | --- |
| 正文区 | 等宽字体显示完整字符画，字号按列数自动缩放铺满宽度，可长按选中 |
| 信息行 | `网格 96×48 · 4608 字符` |
| 复制 | 整段字符画进剪贴板 |
| 存为 TXT | 存成 `.txt` 到系统下载目录 |
| 分享 TXT | 通过任意 App 分享出去（走缓存 + FileProvider，免权限） |

**导入文字面板**（底部「导入」或菜单）

| 部件 | 说明 |
| --- | --- |
| 输入框 | 等宽字体，7~14 行，直接手打或粘贴 |
| 从剪贴板粘贴 | 一键填入剪贴板内容 |
| 打开 TXT 文件 | 从文件管理器读一个 `.txt` 进来 |
| 信息行 | 实时显示 `网格 96×48 · 4608 字符`，边输边更新 |
| 输出宽度 | 滑块，240 ~ 2160 px，默认 1080 px |
| 清空 / 生成图片 | 清掉输入 / 关面板并出图 |

出图后跟正常转换的结果完全一样，能存 PNG、分享、进样式面板调参数——**调参数会实时重渲染**，不用重新粘贴。

字符表是双向的：正向「亮度 → 字符」，反向「字符 → 亮度」。表外字符做就近替换（`"`→`'`、`\`→`/`、`~`→`-`），中文等非 ASCII 一律当实心块处理。行高按 `字宽 / textAspectRatio` 算，所以**导出再导入，长宽比不会越滚越歪**。

**导入后的颜色（分两种情况）**：

- **txt 里带 ANSI 颜色码**（1.2.0 导出过真彩 / 16 色格式）→ 颜色从转义序列里原样读回来，**一格不差**。纯字符那种信息层面的丢失被绕过去了。
- **txt 里只有字符** → 颜色还原不了，这是信息层面的丢失。「彩色」风格走**伪彩色**——按格子亮度在一条光谱上取色：

| 亮度 | 颜色 |
| --- | --- |
| 暗（空格 / `.`） | 深紫 `#3B1F6E` |
| ↓ | 蓝 `#2D6EDE` |
| 中 | 青绿 `#24C9A8` |
| ↓ | 金黄 `#F2C230` |
| 亮（`@` `&`） | 红 `#F2444E` |

出来的观感接近热力图。其余风格（终端绿 / 深海 / 极简 / 报纸）本来就不开彩色，导入文字时和以前一样是单色。

### 文本格式：纯字符 / 16 色 / 真彩（1.2.0 新增）

「文字结果」面板（工具栏 `A` 图标）里多了一排标签，随时切换、随时重编码：

| 格式 | 原理 | 体积参考（96×48 = 4608 格） | 适合 |
| --- | --- | --- | --- |
| **纯字符** | 只有字符 | 约 4.7 KB | 任何地方都能看，最干净 |
| **16 色（PC-98 风）** | 中位切分挑 16 个代表色，每格吸附到最近的 | 约 63 KB | PC-98 画师的手感 |
| **真彩（ANSI）** | 每格独立 RGB，无损 | 约 202 KB | 颜色原样保留 |

切换后预览区立刻重新渲染，**所见即所得**（把 ANSI 还原成彩色文本显示，不是把转义符摊出来），下方同步显示「用了 N 色 · 体积」。选择会记住。

**PC-98 16 色**照搬了两条硬约束：同屏 16 色（中位切分**按画面自动选色**）+ 每通道 4 bit（16 级，即 4096 色那张调色板）。所以调色板里每个通道值一定是 **17 的倍数**（15 × 17 = 255），这就是 PC-98 的真实精度。

**几个容易记混的数字**（PC-9801 经典图形模式）：

| 概念 | 实际值 |
| --- | --- |
| 同屏能显示几种色 | **16 色**（更早的 PC-9801VM/UV 只有 8 色，插 PC-9801-24 扩展板才到 16） |
| 调色板一共多少色 | **4096 色** |
| 调色板精度 | **12 位** = 每通道 4 bit = 每通道 16 级 |
| 每像素占多少位 | 4 bit |

注意 **16 色 ≠ 16 bit**。16 bit 色是 **65536** 色，那是 PC-9821 之后某些模式的事，跟经典 PC-98 游戏画面不是一回事。4096 色的来源是 4 bit × 3 通道 = **12 bit**。

另外，PC-98 的 16 色**不是硬件写死的固定色表**，而是一张**可编程调色板**——每个程序（每张图）自己往里填，所以每张图的 16 色都不一样。我用五组不同色系的画面实测过：挑出的调色板两两之间的重叠是 **0/16**，完全跟着构图走。

**和「只保留色块」叠起来 = 复古像素画**（1.3.0）：

```
原图 ──► 色块降采样 ──► 挑 16 色 + 吸到 12 位 ──► 复古像素画
```

实测 16×8 = 128 个色块，量化后恰好 16 色、**16 个色位全部用上**、全在 12 位精度上。128 块用 16 色画出来，正是当年 PC-98 画师的处境。

**ANSI 真彩**用的是 `ESC[38;2;R;G;Bm` 序列，同色连续只写一次转义，行尾重置。解码时还兼容别处来的 `ESC[31m`（16 色）、`ESC[38;5;Nm`（256 色），粗体/下划线这类参数忽略不误伤。

> **注意**：ANSI 真彩**不是所有地方都能显示**。Windows 记事本要 Win10 1903 起才认；VS Code、终端、`less -R` 都没问题。
> 不支持的地方会看到一堆 `[38;2;...m`。想给谁都看得，导出**纯字符**格式。

### 怎么玩出 PC-98 味（1.4.0 大改）

**最省事的办法**：打开「样式」→ 预设标签里点 **`PC-98`**。一下全配好（320 列 + 色块 + 16 色 + 网点抖动）。

**想自己调**：

1. 选一张图（galgame 的 CG 最合适——本来就是 16 色画的）
2. 打开「样式」→ 开 **`只保留色块`** 和 **`PC-98 画风`**
3. 「字符宽度」拉到 **80 ~ 160**（列数越少块越大，颗粒感越强）；想更贴近原作就试 **320**——PC-98 是 640×400，横向对折差不多
4. 「中间色处理」选 **网点抖动**（默认）或 **误差扩散**——渐变色全靠这个用 16 种颜色"拼"出来
5. 要导出去看：工具栏 `A` → 选 **「16 色（PC-98 风）」**，颜色码全是 17 的倍数

### PC-98 画风（1.4.0 新增）

「PC-98 画风」开关照搬 PC-98 的两条硬约束：**同屏 16 色** + **每通道 4 bit（4096 色板）**。

| 功能 | 说明 |
| --- | --- |
| **自动取色**（默认） | 用中位切分从画面里挑 16 个最有代表性的颜色。每张图挑出来的都不一样——PC-98 没有固定色表，那 16 色是每个程序自己往调色板里填的 |
| **手动选色** | 点「调色板」进面板：4 套现成的（PC-98 标准 16 色 / 怀旧暖色 / 冷调夜色 / 16 级灰阶）任选，或点任一色块用三根滑杆逐通道调（每通道 0~15 级 = 12 位精度），也能一键回「自动取色」 |
| **中间色处理** | `不抖动` / `网点抖动`（默认，Bayer 8×8）/ `误差扩散`（Floyd–Steinberg） |

**为什么需要"中间色处理"**：16 色能直接画出来的只有 16 种，像渐变这样的中间色按理画不出来。
抖动的办法是让**相邻格子轮流用两种颜色**，隔远看合成成中间色——就是老杂志印刷网点那套把戏。

最能说明问题的是这个例子：纯灰 `#888888` + **只有黑白两色**的调色板。

| 模式 | 结果 | 平均亮度 |
| --- | --- | --- |
| 不抖动 | 整片被压成**纯白** | 255（原灰 136，差 119） |
| 网点抖动 | 被拼成**黑白相间**的网点 | 143（差 **7**） |

抖动幅度不是写死的魔数，是按「调色板里相邻两色的平均距离」算的，换任何一套 16 色都能自适应。

实测（`verify_pc98_dither.py`）一条横向渐变跑三档，量「隔远看」的误差（8×8 块平均色差，越小越像）：

| 模式 | 逐格色差 | 8×8 块平均误差 |
| --- | --- | --- |
| 不抖动 | 31.20 | 27.34 |
| 网点抖动 | 32.71 | **18.26** |
| 误差扩散 | 37.91 | **5.02** |

左边那列变大**不是 bug**——抖动的本质就是让单格"故意选得不太准"来换局部平均的准确。
用逐格误差评价抖动是错的指标。

### 样式设置（重点）

点右上角「样式」或在预览区任意位置点一下底部弹出面板：

**预设风格（7 个一键套用）**

| 预设 | 效果 |
| --- | --- |
| 终端绿 | 黑底 + 亮绿字符（`#4CE38B`），经典终端观感 |
| 报纸 | 浅底 + 深色字符 + 字符反转，像旧报纸排版 |
| 彩色 | 保留原图颜色 + 65% 色彩填充，最接近原图的观感 |
| 极简 | 少量字符、高对比，线条化 |
| 深海 | 深蓝底 + 青色字符 |
| **PC-98** | **1.4.0 新增**。320 列 + 色块 + 16 色量化 + 网点抖动，一步到位 |
| 自定义 | 手动调过任何参数后自动切到这个 |

**手动参数**

| 参数 | 范围 | 作用 |
| --- | --- | --- |
| **只保留色块** | 开 / 关 | **1.3.0 新增**。整格填该格的原图颜色，不画任何字符——等于把画面降采样成马赛克。块大小用「字符宽度」调 |
| **PC-98 画风** | 开 / 关 | **1.4.0 新增**。把颜色压到一张 16 色调色板上（4096 色板，每通道 4 bit）。只管配色，和「只保留色块」是**两个独立开关** |
| **中间色处理** | 不抖动 / 网点抖动 / 误差扩散 | **1.4.0 新增**。16 色画不出的中间色（渐变）用点阵组合糊出来。不抖动时会置灰 |
| **调色板** | 自动 / 手动 16 色 | **1.4.0 新增**。默认按画面自动取色；也可以 4 套内置任选或逐色逐通道手调。不抖动时会置灰 |
| 字符宽度 | **16 ~ 1024** 列 | 字符网格的横向列数。列数越大越细腻，转换也越慢。色块模式下就是块的大小。**数字可以点一下直接输入** |
| 原图彩色填充 | 0 ~ 100% | 每个字符背后垫一块原图颜色的底，百分比是透明度。**数字可以点一下直接输入** |
| 字符反转 | 开 / 关 | 亮暗对调。浅色底上开着更好看 |
| 颜色反转 | 开 / 关 | 把字符形状从色块里「抠」出来，负片效果 |
| 保留原图颜色 | 开 / 关 | 关掉就是强制单色 |
| 等宽字体 | 开 / 关 | 让字符排布更整齐，更像终端 |
| 文本预览 | 开 / 关 | 直接看字符本身（可长按选中复制），而不是看渲染出来的图 |

「恢复默认」一键回到出厂参数（**含关掉色块模式**）。

> **关于 1024 列这个上限**：放开列数就必须加个总格子数的闸——列数是你说了算的，
> 行数是按长宽比算出来的，一张竖图 1024 列就能到上千行。
> 所以网格格子总数封顶 **1,500,000**，超了会把**行数**砍下来
> （极端长宽比的图会被略微压扁，好过直接 OOM）。

> **点数字直接输入**：拖滑杆很难精确停在某个值上（想试 512 列，滑杆上根本对不准）。
> 输入范围外的值会提示一句、**不动**当前值——边删边打的过程中必然是空字符串，
> 不能因为一个中间态就把调好的参数清掉。

> **色块模式下会自动置灰的选项**：字符反转、颜色反转、保留原图颜色、等宽字体、原图彩色填充。
> 这几项在色块模式下不参与运算（没有字符可画，配色也不该被「单色」掐掉），
> 置灰是免得点了没反应。色块模式一律用原图颜色——不然就是一整块纯色，什么也看不见。

> **PC-98 画风关着时会自动置灰**：「中间色处理」和「调色板」。
> 同理——16 色没开，这两项算都不算，点上去没反应比按钮不可用更让人困惑。

## 三、算法说明

核心是 BT.601 亮度 + 92 级字符表，逐格映射：

1. 按「字符宽度」把原图缩放到对应的字符网格尺寸。字符本身高宽比不是 1:1，所以缩放时纵向要多除一个比例系数，否则画面会被压扁。
2. 对每个网格单元求平均颜色，按 BT.601 公式算亮度：
   `luma = 0.299R + 0.587G + 0.114B`
3. 亮度去查一张 92 项的字符表（从最稀疏的 `空格` 一路排到最密的 `@`），拿到该格用哪个字符。
4. 逐格绘制：先铺底色（如果有彩色填充就垫原图颜色），再把字符画上去。

字符表（92 级，从暗到亮）：

```
 .-':_,^=;><+!rc*/z?sLTv)J7(|Fi{C}fI31tlu[neoZ5Yxjya]2ESwqkP6h9d4VpOGbUAKXHm8RD#$Bg0MNWQ%&@
```

这套逻辑跟原仓库 `AsciiArtImageFilter` 是逐字节对齐的，算法没改动，只是搬了过来。

**反向（1.1.0 新增）**：字符 → 亮度。每个字符在 92 级表里的下标反查回亮度值，重建成灰度网格，再走同一套 `renderGrid` 渲染。用 Python 单独验证过：92 个字符全能定位，亮度来回转换最大偏差 1 级（平均 0.196 级），没有任何字符偏差超过 1 级。

**PC-98 画风的两步（1.4.0 新增，都在 `Pc98Quantizer` 里）**：

1. **量化（中位切分 median cut）**——从画面里挑 ≤16 个代表色。把所有格子塞进一个桶，
   反复把某个桶沿最宽通道从中间劈开，直到色数够了，每个桶取平均色。
   两个容易写错、都会白白浪费色位的地方（1.3.0 修掉的那个 bug）：
   - **判停看「不同颜色的个数」，不看「桶的个数」**。平均色会被吸附到 12 位网格上，
     两个不同的桶很容易撞到同一格点；按桶数判停就会剩一堆重复色（16 个槽位只给出 6 种）。
   - **选桶要按「桶内还有几种量化色」挑，不能只看原始通道跨度**。按跨度挑会挑到
     「跨度很大但量化后只有一种色」的桶，白劈一次。
   - 大块平涂的画面（正是 PC-98 CG 那种）最容易踩这两个坑。
2. **抖动（把已有 16 色映射到每个格子）**——三档：
   - `不抖动`：每格直接取最近色（按加权距离 `3R² + 6G² + B²`，权重偏绿，接近人眼）。
   - `网点抖动`：Bayer 8×8 阈值矩阵，给每格加一个固定偏移再取最近色。颗粒规则、稳定。
     偏移幅度取「调色板内相邻两色的平均距离」，不用魔数——换任何一套 16 色都能自适应。
   - `误差扩散`：Floyd–Steinberg，把「本来想显示的颜色」与「实际给的颜色」之差，
     按 7/16、3/16、5/16、1/16 摊给右边和下一行的邻居。用浮点缓冲带上小数，不然误差会被截断抹平。

## 五、签名信息

release 包用固定密钥签名，**所有版本共用同一个密钥**，所以可以直接覆盖安装升级。

> **keystore 与口令不写在本文档里。** 实际值在
> `AsciiConverterApp/keystore.properties`（本机开发用，不入版本库），
> 密钥文件在 `AsciiConverterApp/keystore/asciiconverter.jks`——
> **这两个都要留好**，以后发新版本必须用同一个密钥签，否则手机不认，只能卸载重装。
>
> 要自己出签名 release 包，把它们按上面的路径放好即可；`build.gradle.kts`
> 会自动读 `keystore.properties`。**没有这个文件时 release 会打成未签名包**，
> 仍然能正常编译，所以别人克隆仓库下来直接构建不会卡住。

| 项 | 值 |
| --- | --- |
| keystore 文件 | `AsciiConverterApp/keystore/asciiconverter.jks`（**不公开**） |
| key alias | `asciiconverter` |
| 密钥算法 | RSA 2048 |
| 证书签名算法 | SHA384withRSA |
| 有效期 | 2026-09-17 ~ 2056-09-09（约 30 年） |
| 证书主体 | `CN=ASCII Image Converter, OU=dragonxash, O=dragonxash, L=Beijing, ST=Beijing, C=CN` |
| 证书 SHA-256 | `37c4513128ebfa3c7162eadbd92f1acc12e71ece6e6421d4d5b4fc8163dbb369` |
| 证书 SHA-1 | `667db71aa3377491cc789b5e2f7c47b94c296c24` |
| 公钥 SHA-256 | `f9a8cc9831984244fc155718efa05403792330cbd0da040069a89a3d70e86be2` |
| 签名方案 | APK Signature Scheme v2（minSdk 26，不需要 v1 JAR 签名） |

> 上面这些指纹是**公开信息**，可以用来核对你手上的 APK 是否出自同一个密钥：
>
> ```bash
> apksigner verify --print-certs 你的.apk
> ```

改版本时同步改 `app/build.gradle.kts` 里的 `versionCode`（每次 +1）和 `versionName`。

> **1.4.3 特别要说清楚**：这一版加的是**手势**，而手势是「静态校验一条都测不出来」的东西——

已知的平台差异（不是 bug）：

- 剪贴板读写在 Android 13+ 会弹系统「已粘贴」气泡，这是系统行为
- 「存为 TXT」在 Android 10+ 走 MediaStore 存进「下载」目录；Android 8/9 需要存储权限，第一次点会弹权限框
- 分享 `.txt` 走 FileProvider，个别 App 对 `text/plain` 的支持不如 `image/png`，收不到就换个 App 试
